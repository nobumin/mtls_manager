# mtls_manager

[English](README.en.md)

自社サーバ間の通信を **mTLS（相互 TLS 認証）** で守るための、プライベート CA と証明書の自動更新の一式です。
完全にプライベートなネットワークの中だけで動き、外部のサービスには一切つながりません。

Let's Encrypt はクライアント認証用の証明書の発行を 2026 年に終了しました。公開 CA で mTLS を組むことは
もうできないため、自社で CA を持つ必要があります。mtls_manager は、Let's Encrypt と certbot で
サーバ証明書を扱うのと同じ手軽さで、社内に閉じた mTLS を運用できるようにすることを目指しています。

> **状態: v0.x（開発初期）**。仕様は変わることがあります。本番で広く使う前に、
> 外部のセキュリティレビューを受けることを推奨します（[SECURITY.md](SECURITY.md)）。

## 特徴

- **1 つのバイナリで CA を立てられる**: `mtls-ca` は ACME（RFC 8555）サーバです。証明書の自動更新は、
  付属の `mtls-agent` のほか、`lego` などの標準的な ACME クライアントでも行えます。
- **mTLS に特化**: 証明書 1 枚でサーバ認証とクライアント認証の両方に使えます。有効期間は既定で 24 時間と短くし、
  失効の仕組みに頼らずに済むようにしています。
- **最初から安全側の設定**
  - **EAB（External Account Binding）が必須**: 事前に配った鍵を持つサーバだけが、証明書の発行を依頼できます。
  - 鍵ごとに、発行してよい名前を制限できます（例: `web1.internal.example.com` だけ）。
  - **中間 CA に名前制約（Name Constraints）を付けます**: 中間 CA の鍵が漏れても、許可したドメインの外の証明書は作れません。
  - ルート CA の鍵はオフラインに置き、CA サーバには中間 CA の鍵だけを置きます。
  - CA に接続できる送信元を IP で制限できます。秘密鍵のファイルの権限が 0600 でなければ起動しません。
- **アプリへの組み込みが簡単**: Go のライブラリ（`mtls` パッケージ）を使うと、証明書の自動差し替えと、
  接続相手の名前の許可リストを数行で組み込めます。nginx、curl などの既存のソフトとも組み合わせられます。
- **管理画面（閲覧用）**: 状態の概要・発行済み証明書・EAB 鍵・ログを Web で確認できます。ログインはこの CA が発行した証明書による mTLS で、操作はすべて監査ログに残ります。
- **Linux が主、macOS にも対応**: systemd と launchd の設定例を同梱しています。

## 構成

```
 ┌────────────────────┐   CSR に署名（年に 1 回程度）  ┌─────────────────────────────┐
 │ オフラインの端末   │ ─────────────────────────────▶ │ CA サーバ                   │
 │  ルート CA の鍵    │                                │  mtls-ca（ACME サーバ）     │
 │  mtlsctl root ...  │                                │  中間 CA の鍵・EAB 鍵        │
 └────────────────────┘                                └──────────────┬──────────────┘
                                                                      │ ACME（HTTPS）
                                       ┌──────────────────────────────┼──────────────────────────────┐
                                       ▼                              ▼                              ▼
                              ┌────────────────┐            ┌────────────────┐            ┌────────────────┐
                              │ サーバ A       │   mTLS     │ サーバ B       │   mTLS     │ サーバ C       │
                              │  mtls-agent    │ ◀────────▶ │  mtls-agent    │ ◀────────▶ │  mtls-agent    │
                              │  アプリ        │            │  アプリ        │            │  nginx など    │
                              └────────────────┘            └────────────────┘            └────────────────┘
```

| コマンド | 役割 |
| --- | --- |
| `mtlsctl` | ルート CA・中間 CA の作成と、EAB 鍵（サーバごとの発行許可）の管理 |
| `mtls-ca` | 中間 CA で証明書を発行する ACME サーバ。管理画面（閲覧用）も持つ。発行済み証明書の一覧と失効にも使う |
| `mtls-agent` | 各サーバに常駐し、証明書を取得して期限の前に自動で更新する |
| `mtls`（Go パッケージ） | アプリに mTLS を組み込むライブラリ |

## インストール

Go 1.26 以降が必要です。

```sh
go install github.com/nobumin/mtls_manager/cmd/...@latest
```

別のマシン向けにビルドする場合（例: Linux arm64）:

```sh
GOOS=linux GOARCH=arm64 CGO_ENABLED=0 go build -trimpath -o dist/ ./cmd/...
```

## はじめかた

[導入手順](docs/ja/getting-started.md) に沿って、次の順に進めます。

1. オフラインの端末でルート CA を作る
2. CA サーバで中間 CA を作り、`mtls-ca` を起動する
3. サーバごとに EAB 鍵を発行する
4. 各サーバで `mtls-agent` を起動する
5. アプリに組み込む

## 秘密情報の扱い

このリポジトリには、鍵・証明書・EAB 鍵などの秘密情報を**一切含めません**。

- 秘密情報はすべて、実行時にリポジトリ外のファイル（`/etc/mtls-ca` など）から読みます。
  設定ファイルには秘密情報そのものを書かず、ファイルのパスで指します。
- リポジトリには値の入っていない設定例（`examples/`）だけを置いています。
- テストで使う鍵・証明書は、テストの実行時にその場で作ります。
- `.gitignore` で `*.key` / `*.pem` / `eab.json` などを除外しています。CI の gitleaks で、
  秘密情報が混入していないかを全履歴について検査しています。

## 開発

```sh
go test -race ./...                                           # 単体・結合テスト
go vet ./...
LEGO_BIN=$(which lego) go test -tags interop ./test/interop/  # lego との相互接続試験（/etc/hosts の設定が必要）
```

CI（`.github/workflows/ci.yml`）では、書式、静的解析（staticcheck）、Linux / macOS でのテスト、lego との相互接続試験、
各 OS・CPU 向けのビルド、govulncheck、gitleaks を実行します。
